# 调查：在 corpus v2 上重跑设计证据

**2026-11-15**。
问题是 v1 支持的规则，在 v2 上是否仍有同样的依据。
本次不修改规范，也不修改决策索引中的规则结论。
【待定】标记的是维护者需要裁定的证据变化。

## 输入与口径

语料固定于 v2 清单中的提交。
200 个仓库均已浅克隆、无 blob 预取、稀疏检出。
Ring 的权重是 reference，不计主数字。
正式样本为 199 库，纯人写子集为 185 库。
纯人写仅指清单的 human 标签，不含 mixed。
[清单](../corpus/v2.json)、[选择方法](../selection/selection.md)。

第一方插件归属取自选择阶段的缓存判断。
它保存在新增的 `first_party_addons` 字段中。
`exclude` 匹配的生成路径不计第一方。
两个仓库夹带的 Godot 3 子项目也不计入。
这些子项目在选择阶段就已排除。
v1 的既有第一方规则保持不变。

每库最多取 20,000 个物理行，按完整 `.gd` 文件抽取。
先对排序后的文件用种子 `20261115` 洗牌。
如果加入文件会超过上限，就跳过它并继续。
空行和注释行也占抽样额度。
各调查仍按原来的定义计算代码行或逻辑行。
因此，不同调查的每千行数字不能混用分母。
实际抽中 15,022 个文件、1,453,267 个物理行。
纯人写为 13,207 个文件、1,221,062 个物理行。
文件清单与实际行数保存在抽样审计中。
[全体](v2-rerun/results-v2/sampling.json)、[纯人写](v2-rerun/results-v2-human/sampling.json)。

类型和场景解析仍可读取未抽中的文件。
跨文件的使用次数只统计各脚本原有的第一方范围。
抽样会拆开继承关系和跨文件使用的两端。
这些数字描述抽中的代码，不是完整仓库的上界。
不能把抽样后的零值当成整个仓库绝无这种写法。

引擎类参考固定在 Godot `469659e0617345149cd1eaec2e643d61d130aa6a`。
CI 只检出 `doc/classes/`。
模块和平台的派生元数据补齐其余类，共 1,112 类。
对象 API 描述固定在 godot-cpp 的 `8070599885b6df675fcad033dd032ce44be2b850`。
文件为 `gdextension/extension_api-4-7.json`。
纸面迁移账本仍只描述原来的 FPS 和 Ring。
暗坑清单也只重建已固定的记录，没有重新搜索 GitHub。

v1 的访问器和 await 调查原本只有 14 库。
其他语料调查的 v1 基线是 20 库。
本表保留这些原始范围，不把 v1 补成新的样本。

## v1 修正

- `counts.txt` 补上 `_get` 3 个、`_set` 5 个。
  原有计数不变，正文早已包含这两个数字。
- 成员外部使用从 4,597 降至 4,589。
  只在本文件使用的成员从 13,471 增至 13,479。
  外部使用为每千行 22.5，原来是 22.6。
  游戏组和只被子类使用的成员数不变。
- 跨分支调查的逻辑行从 163,202 增至 163,964。
  Dialogue Manager 增加 702 行。
  phantom-camera 增加 52 行，open-rpg 增加 8 行。
  单元数从 2,989 增至 2,992。
  三种窗口的跨分支重复行数均不变。
  游戏同链密度的舍入从每千行 50.1 修正为 50.0。
  Dialogue Manager 的单元内和测试重复随之增加。

后两项来自已有词法分析器的多行字符串修正。
JSON 的键排序及同频结果的显示顺序也已固定。
这些排序变化不改变计数。
三份 v1 报告的设计结论都没有改变。
[计数](corpus-counts.md#v1-复跑修正)、[成员](member-visibility.md#v1-复跑修正)、[重复](cross-branch-duplication.md#v1-复跑修正)。

## 方法边界

C03 的旧脚本统计所有 Autoload.x = self，不限定函数。
v1 的 6 处中，5 处字面位于 _ready，另 1 处在它调用的 helper。
v2 的 64 处中，54 处字面位于 _ready。
不把这 64 处说成全部直接在 _ready 中执行。
本次另列词法范围，不推演完整调用图。

访问器和 await 提取沿用 v1 的分行口径。
它们把终止换行后的空项也计作一行。
因此，分母会略大于抽样审计中的物理行数。
抽样额度仍严格按 splitlines 的物理行数执行。

String、捕获和 getter 的同名误报已经在样本中显露。
计数器是词法近似，不是 GDScript 编译器。
未抽中的第一方文件也不会贡献自己的使用次数。
不能据此为完整项目证明不存在某种写法。

addons 以外的随附库仍可能按清单算作第一方。
弱引用样本中有 4 处来自游戏随附的 steering-ai 库。
清单的人写标签也不是逐行作者鉴定。
这些限制与选择报告中的已知边界相同。

getter 的字段判据只给机械分类，不能代替全部阅读。
其提取还报告 gaea 一处 lambda 初始化式歧义并跳过。
构造覆盖脚本计到 15,152 个 const 词法位置。
常量调查实际解析了 15,151 个声明，两者没有混用。

## 复现

需要 Python 3.11 标准库和 git。
先按 README 准备固定的引擎 API 与类参考。
如果使用现有 Godot 检出，设置以下环境变量。
脚本从 Git 对象只读，不切换检出。

```powershell
$env:GODOT_REFERENCE = 'C:/godot'
$env:GODOT_REVISION = '469659e0617345149cd1eaec2e643d61d130aa6a'
python fetch.py v1
python fetch.py v2 --jobs 4
python reproduce.py
python rerun.py v2
python rerun.py v2 --human-only
python surveys/v2-rerun/compare.py
python surveys/v2-rerun/survey_compare.py
$env:CORPUS_MANIFEST = 'corpus/v2.json'
python surveys/v2-rerun/review.py --check
python surveys/cross-branch-duplication/test_gdcorpus.py
```

`rerun.py` 将原始提取写入 `work/rerun/`。
只有派生结果进入 `results-v2/` 和 `results-v2-human/`。
保存前，.txt 报告去掉行尾的 ASCII 空格和制表符。
v1 的比较器不做这种清理。
如果新结果与已有结果不同，脚本拒绝覆盖。
人工标签不由复跑自动生成或改变。
